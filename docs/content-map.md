# Content map — ภาพรวมเนื้อหาสำหรับ agent

อ่านไฟล์นี้ก่อนแตะ `src/content/` เพื่อรู้ว่าแต่ละบทมีไว้ทำอะไร โดยไม่ต้องเปิด slides ทุกไฟล์
- รายการสไลด์ทุกอัน (สร้างอัตโนมัติ): `docs/content-index.md`
- แหล่งข้อมูลและเหตุผลเชิงวิจัย: `docs/research.md`
- **แก้ไฟล์นี้ด้วยมือเมื่อเพิ่ม/ลบ/เปลี่ยนจุดประสงค์ของบท**; หลังแก้ `slides.ts` ให้รัน `pnpm content:index`

## เรื่องทั้งหมด

Deck สำหรับผู้เรียน (ภาษาไทย) ว่า "เว็บที่ดีต้องเป็นอย่างไร" ผ่านตัวเลขจากงานวิจัย ไม่ใช่ทฤษฎี
โครงเรื่อง: **คนอ่านแบบสแกน → เว็บต้องเร็ว → ต้องเข้าถึงได้ → สีคือตัวอย่างของการเข้าถึง → สรุปสามข้อ**
หลักการ: 1 สไลด์ = 1 ความคิด, ตัวเลขเป็นพระเอก, ทุกตัวเลขมีแหล่งที่มา (`src`)

## บท (ลำดับ = ลำดับในสไลด์ และใน `src/content/index.ts`)

| # | slug | จุดประสงค์ (ทำไมมีบทนี้) | ข้อความหลักที่ผู้เรียนต้องได้ | แหล่งหลัก | สถานะ |
|---|---|---|---|---|---|
| 1 | `reading` | ตั้งฐาน: ออกแบบเพื่อ "คนสแกน" | คนอ่านจริงราว 25% ที่เหลือสแกน → เนื้อหาต้องมีโครงสร้าง | Nielsen Norman Group | ร่าง (3 สไลด์) |
| 2 | `speed` | เหตุผลเชิงธุรกิจของความเร็ว | LCP ≤ 2.5s; ช้าลง 1s = conversion −7%; เร็วขึ้นมีผลจริง (Rakuten +33%) | web.dev, Conductor | ร่าง (5 สไลด์) |
| 3 | `accessibility` | ปัญหาจริงของเว็บทั่วไป | 95.9% ของหน้าแรกมีข้อผิดพลาด WCAG; contrast ต่ำคืออันดับ 1 (79.1%) แต่แก้ง่าย | WebAIM Million 2026 | ร่าง (4 สไลด์) |
| 4 | `color` | เจาะลึกปัญหา contrast → เป็นเหตุผลของ design system นี้ | ไม่ต้องดำบนขาวสนิท: 13:1 สบายตากว่า 21:1; ต่ำกว่า 4.5:1 อ่านยาก | WCAG 2, APCA | ร่าง (2 สไลด์) |
| 5 | `summary` | ปิดเรื่อง | สแกนง่าย · เร็ว · ทุกคนใช้ได้ | — | ร่าง (1 สไลด์) |

## ความสัมพันธ์ระหว่างบท

- `accessibility` (ตัวเลข contrast 79.1%) → `color` (ทำไม/ทำอย่างไร) — สองบทนี้ต่อเนื่องกัน อย่าย้ายห่างกัน
- `summary` สรุป 3 ข้อจากบท 1–3; ถ้าเพิ่มบทใหม่ ให้ทบทวนข้อความสรุป
- สไลด์ compare ของ `color` ใช้ hex ดิบโดยตั้งใจ (สีคือตัวอย่าง) — เป็นข้อยกเว้นเดียวของกฎ "ห้าม #000/#fff"
- ตัวเลขที่ใช้ซ้ำในหลายที่ (เช่น 79.1%) ต้องแก้ให้ตรงกันทุกจุด: ค้นด้วย `grep` ก่อนแก้

## เมื่อเพิ่มเนื้อหา

1. เพิ่มสไลด์: `src/content/chapters/<slug>/slides.ts` (ดู `design.md` § การเพิ่มเนื้อหา)
2. บทใหม่: `meta.ts` + `slides.ts` + ลงทะเบียนใน `src/content/index.ts`
3. อัปเดตตารางด้านบน แล้วรัน `pnpm content:index`
4. ตัวเลขใหม่ต้องมี `src` และบันทึกที่มาใน `docs/research.md`
5. `pnpm lint && pnpm build && pnpm content:check`
